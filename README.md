Source of my personal website, <https://raulpe7eira.tech>: a bilingual home page and resume, generated by a small Elixir app and served by GitHub Pages from `docs/`. The published site is plain HTML, CSS and JavaScript, with no frontend framework or bundler.

## Features

- **Bilingual**: English (`/`) and Portuguese (`/pt/`) pages, linked with `hreflang`
- **Resume**: `/resume/` page and PDF download in both languages, built from the same data
- **9 color themes**, remembered per visitor
- **SEO**: Open Graph and Twitter cards, JSON-LD (`Person`), canonical URLs, `sitemap.xml` and an `llms.txt` for AI assistants
- **Installable**: web manifest with icons, a maskable icon, a "Resume" shortcut and screenshots; opens in a `minimal-ui` window
- **Checked**: CI fails on a broken local link, an unused asset or a page that differs from the generator's output

## Development

Requires Erlang/OTP and Elixir as pinned in `mise.toml` (`mise install`). Commands that print PDFs or screenshots need Chrome (set `CHROME=/path/to/chrome` if it isn't found).

```sh
mix deps.get
mix site.build      # render the pages and the resume PDFs into docs/ (--no-pdf skips the PDFs)
mix site.server     # build, serve docs/ at http://localhost:8000 and rebuild on changes (--no-pdf, --no-build, --no-watch)
mix site.check      # fail on broken local links or unused files in docs/
mix precommit       # compile with warnings as errors, format, credo, deps audit, tests with coverage, site.check
```

`mix site.server` behaves like GitHub Pages: folders serve their `index.html`, `/resume` redirects to `/resume/` and unknown addresses get `404.html`. While it runs, saving a file in `data/`, `lib/` or `priv/` rebuilds the site (with the PDFs unless `--no-pdf`), and the open pages reload by themselves; a change in `docs/assets/` just reloads them.

### Images

Images are generated from source files kept outside the repo; the kind decides the arguments and how the image looks:

```sh
mix site.images company "Name" logo.png [--center]       # company square on the resume timeline
mix site.images client "Name" logo.png [--boost 1.25]    # client tile on the resume
mix site.images project "Name" logo.png [--boost 1.25]   # project tile on the resume
mix site.images favicons photo.jpg                       # favicons and app icons
mix site.images avatar photo.jpg                         # home page photo
mix site.images screenshots                              # home page screenshots for the web manifest
```

`mix help site.images` explains each kind.

## Updating the content

1. Change LinkedIn first; it is the source of truth.
2. Update the matching file in `data/` (profile, experiences, educations, skills, languages, highlights).
3. New company, client or project: add its logo with `mix site.images company|client|project` (a test fails if a logo is missing).
4. Run `mix site.build` (with PDFs, since the resume changed), then `mix site.check` and `mix precommit`.
5. If the home page looks different, run `mix site.images screenshots`.

## Layout

| Path | What it is |
| --- | --- |
| `lib/`, `priv/templates/` | generator code and EEx templates |
| `priv/gettext/` | interface text in English and Portuguese |
| `data/` | resume data (JSON, validated by Ecto schemas) |
| `test/` | ExUnit tests |
| `docs/` | published site; HTML pages here are generated, don't edit them by hand |
| `docs/assets/` | CSS, JS, fonts and images |
| `docs/downloads/` | resume PDFs (generated) |

CI (GitHub Actions) runs the same checks, posts coverage to Coveralls (minimum 90%) and fails if `mix site.build --no-pdf` changes anything in `docs/` or `mix site.check` finds a problem. Dependabot keeps Mix deps and GitHub Actions up to date.
