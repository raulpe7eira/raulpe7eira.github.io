# CLAUDE.md

## Project Overview

Personal website for Raul Pereira (raulpe7eira) — a software engineer with 20+ years of experience. Hosted on GitHub Pages at https://raulpe7eira.tech.

## Architecture

The published site lives in `docs/` (GitHub Pages source: branch `master`, folder `/docs`; `docs/.nojekyll` disables Jekyll). Everything outside `docs/` (generator, tests, README, LICENSE, this file) is not served.

### Generator (Elixir)

HTML pages are generated by a Mix project at the repo root:

- `mix site.build` renders the pages and prints the resume PDFs into `docs/`; `--no-pdf` skips the PDFs (`lib/mix/tasks/site.build.ex`)
- `lib/site.ex` — `Site.build/2`, writes the pages (and the PDFs with `pdf: true`)
- `lib/site/pdf.ex` — `Site.Pdf`: prints the resume PDFs with headless Chrome (ChromicPDF; `CHROME=/path` if not found) and their `thumb.png` with `pdftoppm` (poppler). Not run by tests or CI, and left out of coverage (`coveralls.json`)
- `lib/site/pages.ex` — `Site.Pages`: builds the assigns per page and renders them in memory (pure, no file IO), including the HTML printed to each PDF
- `lib/site/resume_view.ex` — `Site.ResumeView`: turns the resume data into plain maps in one language for the templates (translations, dates, logo names)
- `lib/site/labels.ex` — `Site.Labels`: Gettext labels for data values (months, work modes, skill types, proficiencies), one clause per value so `gettext.extract` finds every key
- `lib/site/html.ex` — `Site.Html`: `escape/1` for data text in templates, and stripping whitespace between tags (resume templates are indented, the output is not)
- `lib/site/locale.ex` — `Site.Locale`: per-language settings (paths, URLs, locale codes) and `with_locale/2`
- `lib/site/gettext.ex` + `priv/gettext/` — `Site.Gettext`: interface text (titles, labels, alt texts). msgids are short dotted keys (`gettext("footer.made_with")`), so both `en` and `pt_BR` `.po` files hold the text and tests fail if any key is missing in either. After adding or changing a `gettext(...)` call, run `mix gettext.extract --merge` (also part of `mix precommit`) and fill in the new entries in both locales. Content that comes from LinkedIn in both languages is not translated via Gettext
- `lib/site/templates.ex` — compiles the EEx files in `priv/templates/` into functions
- `priv/templates/layout.html.eex` — shared `<head>`, toolbar, header and footer for every page
- `priv/templates/home/{en,pt}.html.eex` — home page text; `priv/templates/resume/page.html.eex` — resume section; `priv/templates/resume/pdf.html.eex` — the PDF (own CSS, fonts from `priv/fonts/`); `priv/templates/partials/` — social links, JSON-LD
- Templates can call `gettext/1,2` for labels and must `escape/1` text that comes from `data/`

Resume data lives in `data/` as JSON and is validated by Ecto embedded schemas (no database):

- `data/profile.json` (`Site.Resume.Profile`), `experiences.json` (`Experience` → `Role` → `Reference` for clients/projects), `educations.json` (`Education`), `skills.json` (`Skill`), `languages.json` (`Language`)
- `Site.Resume.load/1` reads them with Elixir's native `JSON` and returns `{:ok, %Site.Resume{}}` or `{:error, [{"file.json[index]", errors_by_field}]}`; `load!/1` raises
- Content that LinkedIn has in both languages is `{"en": …, "pt": …}`; skills stay as on LinkedIn (untranslated); skill `type` (one of the groups in `Site.Resume.Skill`) and language `proficiency` are enums whose labels come from Gettext (`Site.Labels`)
- Names are kept exactly as on LinkedIn; `Site.Resume.display_name/1` shortens a few (BRQ, Supply Midia, Sonda, Drive, PUC-Rio, UniverCidade)
- Descriptions are one text per language: paragraphs separated by a blank line, bullet lines starting with `- `
- Dates are `"YYYY-MM-01"` (LinkedIn has month precision); roles of a company are newest first, only the first may be open, and they must not overlap
- Never put private data in `data/` (the repo is public): no birth date, phone or address

Keep the split between rendering (pure, `Site.Pages`) and IO (`Site.build/1`, Mix tasks): the renderer may later back other front ends (e.g. an MCP server that extracts LinkedIn data and returns HTML/PDF).

Generated: the home and resume pages in both languages, the resume PDFs and their thumbnails. **Never edit generated files in `docs/` by hand** — change the template or the data and run `mix site.build`; CI runs `mix site.build --no-pdf` and fails if `docs/` is out of date (PDFs are not checked: Chrome stamps each one with its creation date, so they change on every build). Not generated yet (being migrated): `sitemap.xml`, `llms.txt` and `404.html`.

In the PDF, companies whose last role ended up to 2012 are condensed under "Earlier experience" (`Site.ResumeView`), to keep it at two pages.

Styles, scripts and images are source files edited directly in `docs/assets/` and `docs/images/`, shared by all pages. Local paths are root-absolute (e.g. `/images/cover.jpg`, `/assets/css/base.css`), so test with a local server rooted at `docs/`, not `file://`.

### Quality

- Erlang/OTP and Elixir pinned in `mise.toml` (used locally and by CI via `jdx/mise-action`)
- `mix precommit` — `compile --warnings-as-errors`, `deps.unlock --check-unused`, `gettext.extract --merge`, `format`, `credo` (strict, see `.credo.exs`), `deps.audit` (mix_audit), `coveralls` (tests + coverage, minimum 90% in `coveralls.json`)
- CI: `.github/workflows/ci.yml` runs the same checks, posts coverage to Coveralls (`mix coveralls.github`) and runs `mix site.build --no-pdf` + `git diff --exit-code docs/`
- Dependabot (`.github/dependabot.yml`): weekly updates for Mix deps and GitHub Actions
- Not used on purpose: Dialyzer (Elixir 1.20's type checker covers it), Sobelow (no Phoenix), ex_check (`mix precommit` is enough)

## Features

- **Bilingual**: English (`/`, default) and Portuguese (`/pt/`) as separate indexable pages, linked via `hreflang` alternates (in `<head>` and `sitemap.xml`); the EN/PT button is a link to the other page
- **Resume**: `/resume/` and `/pt/resume/`, reached via the Resume/Currículo toggle in the toolbar and the "professional experience" link; listed in `sitemap.xml` and `llms.txt`
- **9 themes**: Dracula (default), Nord, Gruvbox, Catppuccin, Solarized Dark, Tokyo Night, Rose Pine, One Dark, Dark — defined in `base.css`, selected via `data-theme` on `<html>`, persisted in localStorage (`theme`)
- **SEO**: Open Graph, Twitter Card, JSON-LD (Person schema), canonical URL, meta description, hreflang alternates — all localized per page
- **Analytics**: Google Analytics (G-4QXLD8YPLP, loaded by `docs/assets/js/analytics.js` only on raulpe7eira.tech) + Plausible Analytics (site script `pa-*.js`, init in `analytics.js`; outbound links and file downloads toggled in the Plausible dashboard; ignores localhost by itself)
- **Social icons**: GitHub, LinkedIn, X, Bluesky, Instagram, Facebook, Strava, IMDb, Last.fm, Email — using inline SVG from Simple Icons
- **Responsive**: 3 breakpoints (480px, 768px, 1200px)
- **Accessibility**: Semantic HTML, ARIA labels, keyboard navigable

## Tech Stack

## Conventions

- Elixir: descriptive variable names (no single letters like `t`), one `alias` per line (no `alias Site.{A, B}`), `mix format` + `mix credo` (strict) clean; tests for new code (coverage stays at or above 90%)
- Tests: one `describe "function/arity"` per public function; one behavior per `test`, named after that behavior (e.g. "Portuguese home is under /pt/")
- No inline `style="…"` attributes, `<style>` blocks or `onclick` handlers (except the standalone `404.html`): CSS in `docs/assets/css/`, JS in `docs/assets/js/` (loaded with `defer`); the only inline script is the head theme snippet
- Theme colors use CSS variables (`--bg`, `--fg`, `--comment`, `--cyan`, `--green`, `--orange`, `--pink`, `--purple`, `--red`, `--yellow`)
- Footer colors (heart red, R3M green, TECH purple) and theme-panel swatches are fixed in `base.css` and do not change with themes; hovering the footer link scales it and makes the heart beat
- Header hover grows the header and spins the avatar; when the site is entered, reloaded or opened in a new tab (not on internal navigation or back/forward) `nav.js` replays that hover once via the `.intro` class; disabled with `prefers-reduced-motion`
- External links use `target="_blank" rel="noopener noreferrer"`
- Portuguese content elements have `-pt` suffix IDs, English have `-en` suffix
- SVG icons live in the sprite `docs/assets/icons.svg` as `<symbol id="…" viewBox="0 0 24 24">` (social icons from Simple Icons); pages reference them with `<svg viewBox="0 0 24 24"><use href="/assets/icons.svg#id"/></svg>` and color them via CSS `fill` on the `<svg>`
